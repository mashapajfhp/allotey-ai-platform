## Preliminary Overview

TypeDB is a strongly-typed database with a rich type system that combines relational, document, and graph database strengths. It uses TypeQL, a declarative, functional, and strongly-typed query language. TypeDB 3.0.0 was released December 2024, representing a full rewrite from Java to Rust using RocksDB for storage.

The type system has three root types: **entities** (independent objects), **relations** (connections depending on role interfaces), and **attributes** (properties with typed values). All user-defined types subtype one of these three roots. The schema supports full inheritance hierarchies, ownership constraints (`owns`), role-based relation definitions, and uniqueness/key constraints.

## What Is Known

### Type System
- Three root types: entities, relations, attributes
- Full inheritance and interface implementation
- Conceptual data modeling approach (not physical)
- Type hierarchies enable polymorphic queries
- TypeDB 3.0 introduces lists (typed collections where all members share a single type)

### TypeQL Query Language
- Declarative, functional, strongly-typed
- Fully variablizable syntax supporting polymorphic queries
- Patterns mirror TypeDB's type system
- TypeDB 3.0 replaces rules with reusable functions -- a shift from predicate-logic semantics to type-theory semantics
- Functions bridge reasoning and querying in the type system

### Reasoning
- TypeDB 2.x: rule-based inference (forward chaining through type and relationship reasoning)
- TypeDB 3.0: functions replace rules as more powerful, modular, generalizable constructs
- Functions force separation of reasoning from data model
- NEEDS VERIFICATION: current state of reasoning capabilities in 3.0 stable releases

### Storage
- Built on RocksDB
- gRPC/ZeroMQ for communication protocols
- Bazel for build management (Cargo as alternative)

### Deployment Options
- TypeDB Cloud (multi-cloud DBaaS)
- TypeDB Enterprise (self-hosted)
- TypeDB CE (community edition, this repository)

## Potential Relevance

TypeDB's strongest contribution is its **type system design**. The three-root-type model (entity/relation/attribute) with inheritance, interfaces, and constraints provides a rigorous framework for modeling domain ontologies. The shift from rules to functions in TypeDB 3.0 is architecturally interesting -- it suggests that type-theory semantics may be more composable than predicate-logic semantics for knowledge modeling.

However, TypeDB lacks the AI/agent ecosystem integrations (MCP, LangGraph, vector search) that Semantica, TrustGraph, and Graphiti provide. Its value may be more as an inspiration for type system design than as a direct adoption candidate.
