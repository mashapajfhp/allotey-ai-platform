## Preliminary Overview

TerminusDB is an open-source graph database and document store that implements git-style version control for data. It stores JSON-LD documents with typed edges in a knowledge graph, using delta encoding (immutable layers of subject-predicate-object triple changes) rather than mutable state. Every historical commit is immediately queryable, diffs are semantic JSON patches rather than textual hunks, and the database supports branching, merging, squashing, rollback, blame, and time-travel.

The core value proposition: "git for data" -- bringing the collaboration, versioning, and auditability patterns of source control to structured data and knowledge graphs.

## What Is Known

### Data Model
- Hybrid document + graph model
- JSON/JSON-LD documents as primary data units
- Documents decomposed into RDF triples stored in succinct data structures (delta layers)
- Each delta layer is content-addressed and immutable
- Typed edges distinct from property graphs
- `@unfoldable` subdocuments for embedding
- `@metadata` for additional structured information
- Schema enforcement through JSON schema constraints

### Version Control for Data
- Changes tracked at the triple level (not line level)
- Delta encoding: database changes as compact diffs (60% less memory than full snapshots)
- Full suite of revision control: branch, merge, squash, rollback, blame, time-travel
- Push, pull, clone for distributed collaboration
- Every historical commit is immediately queryable
- Semantic JSON patches rather than textual diffs

### Query Languages
- **WOQL (Web Object Query Language)** -- Datalog-based with unification, more expressive than SPARQL for recursive graph traversal and reasoning
- **GraphQL** -- full graph query capability with path queries
- **REST API** -- graph queries with deep link discovery
- Triple-based reasoning across document boundaries

### Storage Architecture
- Succinct immutable data structures (write-once, read-many)
- RocksDB backend for layered delta storage
- Immutable commit log for time-travel queries
- In-memory graph database management
- TerminusDB 12: range queries over succinct data with constant-time retrieval

### TerminusDB 12 Features
- ISO8601 Allen Interval Algebra for temporal reasoning
- Arbitrary precision rational mathematics (xsd:decimal)
- Unstructured JSON support with git-for-data versioning
- High-precision decimals for financial applications
- WOQL language improvements
- NEEDS VERIFICATION: 92% faster than Neo4j for multi-branch queries (internal benchmarks)

### Client Libraries
- Python (v12): full-featured official client
- JavaScript (v12): browser and Node.js support
- Rust: community-contributed
- Elixir: community-contributed

### Deployment
- Docker with docker-compose
- Snap-installable CLI
- Enterprise version: clustering, backup APIs, higher write performance

## Potential Relevance

TerminusDB's strongest contribution is its **versioned data model with semantic diffs**. The idea that every change to a knowledge graph is tracked as an immutable delta layer, with full git-style branching and merging, is directly applicable to ontology version control in an intelligence platform. You could:

- Branch an ontology to test schema changes before merging to production
- Diff two versions of the knowledge graph to understand what changed
- Roll back to a previous state if a bad ingestion corrupts the graph
- Clone knowledge graphs across environments (dev/staging/prod)

However, TerminusDB lacks AI/agent ecosystem integrations (no MCP, no vector search, no LLM integration). Its value is primarily as an inspiration for versioned knowledge management rather than a direct component.

The Allen Interval Algebra support in v12 is interesting for temporal reasoning, potentially complementing Graphiti's bi-temporal fact model.
