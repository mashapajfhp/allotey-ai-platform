## Key Evaluation Criteria

For each technology, research should assess:
1. **Isolation strength** — what is the security boundary? Process? Kernel? Hardware?
2. **Startup latency** — how quickly can a sandbox be created? (interactive use needs < 500ms)
3. **Resource control** — CPU limits, memory limits, execution timeout, filesystem quotas
4. **Network isolation** — can network access be fully blocked? Allowlisted?
5. **Library availability** — can common Python libraries (numpy, pandas, matplotlib) be pre-installed?
6. **GPU passthrough** — can sandboxed code access GPU hardware for ML workloads?
7. **Input/output marshalling** — how are data and files passed in and out?
8. **Operational complexity** — what infrastructure is required to run this?
9. **License** — confirm open-source license compatibility
10. **Self-hosted viability** — can this run entirely on our infrastructure?

## Research Template

Each project research file should cover:
1. **License verification** — confirm license and any commercial tier restrictions
2. **Isolation model** — how does isolation work? What is the attack surface?
3. **Performance characteristics** — startup time, overhead, throughput
4. **Integration fit** — how does this integrate with the platform's agent runtime and Kubernetes deployment?
5. **Community and maturity** — activity, governance, production users
6. **Adopt/Wrap/Study decision** — recommendation for the platform
